# SiteSafe: PPE compliance with privacy

On-device computer vision that checks whether construction workers are wearing the PPE their work area requires, in photos, 10 to 30 second clips and live camera video. Faces are blurred, nothing is uploaded, and the result is a site-level compliance figure for the safety officer, never a record about an individual.

## What it does

- Each person gets a box: **green, solid, tick** when compliant; **red, dashed, cross** when required PPE is visibly missing (the missing items are listed); **blue, dotted, question mark** when the model is not confident and the officer should check.
- Required PPE is set by a site profile: general (helmet, vest), full (plus gloves, boots), cutting and grinding (plus goggles).
- PPE is matched to people by intersection over the PPE box's own area plus a position check (helmet near the top, boots near the bottom).
- Clips: frames sampled at 2 to 5 fps, an IoU tracker with anonymous worker numbers, and temporal smoothing (a violation needs 3 of the last 5 frames).
- Danger zones drawn as polygons; people inside a zone or close to a detected forklift are flagged.
- Faces detected with YuNet and blurred before anything is shown or exported. Detection runs on the original frame held in memory.
- Compliance percentage, counts by PPE type, a dashboard, and PDF and CSV incident reports generated in the browser.
- Extras: live camera HUD, Inspector Challenge (you against the model), Weather Lab (diffusion-generated night, rain, fog and dust versions with both detectors), an optional small vision-language model that writes a summary whose every claim is checked against the detector.

## Run every step

Each step is one command. With `make`: `make data`, `make train`, and so on. Without `make` (Windows): `python tasks.py data`, `python tasks.py train EPOCHS=30`. `python tasks.py` lists all targets.

| Step | Command |
|---|---|
| Download data (CC BY 4.0) and YuNet, fix `data.yaml` path | `python scripts/download_data.py` |
| Seeded, stratified 700 / 200 / 100 split | `python scripts/make_split.py` |
| Dataset statistics | `python scripts/dataset_stats.py` |
| Baselines | `python scripts/baseline_rules.py` and `python scripts/baseline_zeroshot.py` |
| Train | `python scripts/train.py --name base --epochs 100` (or Colab notebook 1) |
| Export to ONNX | `python scripts/export_onnx.py --weights runs/base/weights/best.pt --name sitesafe_base` |
| Calibrate, evaluate | `python scripts/calibrate.py`, `python scripts/evaluate.py ...`, `python scripts/compliance_eval.py` |
| Int8 quantisation | `python scripts/quantize.py` |
| Synthetic data | `python scripts/synth_generate.py`, `python scripts/synth_filter.py`, then train with `--data ppe_synth_diffusion.yaml` (or Colab notebook 2) |
| With vs without synthetic | `python scripts/synth_experiment.py` |
| Studies | `fairness_audit.py`, `failure_gallery.py`, `smoothing_study.py`, `blur_study.py`, `speed_bench.py`, `vlm_hallucination.py` |
| Collect metrics | `python scripts/build_metrics.py` |
| Package web assets | `python scripts/build_web_assets.py` |
| Tests | `python -m pytest -q` and `cd web && npm run typecheck && npm test` |

My own 30-image test set: `python scripts/fetch_own_images.py` (licensed Wikimedia Commons photos, sources in `data/own_test/sources.csv`), person-level labels in `data/own_test/people_labels.json`, scored by `python scripts/own_eval.py`. Extra real-photo data for the improved model: `python scripts/prepare_extra_data.py` (three CC BY 4.0 Hugging Face datasets) and `colab/SiteSafe_Colab_Plus_Training.ipynb`.

## Deploy

All free tiers, no card, no paid API, no serverless functions.

**Vercel (main).** Import the GitHub repo in Vercel, set the root directory to `web`. `web/vercel.json` sets the build, the SPA rewrite, `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (needed for multi-threaded WASM) and long cache headers for `.onnx` and `.wasm`. Every push deploys; every branch gets a preview URL.

**Cloudflare Pages (mirror, on the approved list).** Create a Pages project from the same repo: root directory `web`, build command `npm run build`, output `dist`. `web/public/_headers` carries the same headers. No code change. The build uses relative paths and hash routing, so it also works on GitHub Pages.

**Streamlit Community Cloud (fallback).** New app from the repo, main file `streamlit_app/app.py`. It installs `requirements.txt` (no PyTorch) and reads `models/sitesafe_base.onnx` and the YuNet model from the repo.

The ONNX models are committed (10.7 MB and 0.2 MB, far below the 100 MB limit). The optional summary model (SmolVLM-256M) is loaded at runtime from its Hugging Face model repository by Transformers.js and cached by the browser.

## Privacy by design

- The web app has no server code. Images, frames and faces stay in the browser's memory; the session log is in memory only and disappears when the tab closes. Settings (not images) are kept in local storage.
- The Streamlit app processes uploads in memory for one request; a clip is written to a temporary file only because OpenCV needs a path, and deleted straight after reading.
- Faces are blurred with a down-sample plus Gaussian blur, which removes detail rather than hiding it behind a reversible filter. Strict mode also blurs the face area of people whose face was not found.
- Reports contain counts and anonymous numbers that reset with every analysis.

## Responsible use

SiteSafe supports the safety officer and does not replace an inspection. It must not be used to identify, monitor, score or discipline individual workers. Tell the people in view what the check is for before using it. See `docs/model_card.md`.
